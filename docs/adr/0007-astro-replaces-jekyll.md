# ADR 0007 — Port the website from Jekyll to Astro before building the admin

- **Status:** Accepted (2026-11-16). Phase 0 of the [admin app plan](../admin/ADMIN_APP_PLAN.md)
  must confirm the Astro facts marked *unverified* below before code is written.
- **Date:** 2026-11-16
- **Deciders:** Zack Glick

## Context

The public site is Jekyll: about 500 lines of Markdown, about 1,000 lines of custom layouts and
includes, and `js/checkin.js`. Jekyll was picked because it was familiar and fast, not for
anything specific to it.

The admin app (ADR 0008) and database-driven event pages (ADR 0009) both need pages that are
rendered per request: behind a login for the admin, and from Neon for `/events/YYYY-MM-DD/`.
Jekyll only produces static files. Each change to `_data/luma_events.yml` costs a 15-credit
production deploy, and expired dates fall back to a `/events/* → /` 302 in `netlify.toml`. Future
community features may also sit behind a login.

## Decision

1. **Move the website to Astro** on the existing single Netlify site. Pages are static by
   default, and only the routes that need it are rendered on request through Netlify Functions:
   `/events/[date]`, `/admin/*` and the auth endpoints.
2. **Port first, as its own release.** The first port changes no visuals and no URLs, and the
   admin work starts only after it ships.
3. **The check-in pages are copied, not rewritten.** `checkin/*.html` and `js/checkin.js` move
   byte for byte as static files. `checkin/bocc-afternoon.html` is retired, since the afternoon
   series has ended.
4. **The build becomes Node-only.** Ruby, Bundler and `scripts/generate_event_pages.rb` are
   removed once ADR 0009 lands.

## Alternatives considered

- **Keep Jekyll and add a separate admin.** The admin and event pages would live in a second
  system, and each event change would still cost a deploy.
- **Next.js.** Works, but it is heavier, and pages rendered on request run as functions on every
  view, which uses credits from the 300/month free pool.
- **Admin as HTML generated by functions while Jekyll stays.** It would be rewritten later when
  the public site moved.

## Consequences

- The Google Form replacement ships a few days later, but the admin is built once, in its final
  framework.
- Release check for the port: the list of output files matches the old `_site` (including
  `llms.txt` and `404.html`), the JSON-LD and the CSP are unchanged, and a debug check-in passes
  on the branch deploy.
- *Phase 0 (2026-11-16):* per-route prerendering is confirmed in Astro's docs (`astro` 7.4.12,
  `@astrojs/netlify` 8.2.14). Netlify says framework functions are appended to the user's.
  *Still unverified:* that the existing `[functions]` config still works next to the adapter, in
  a branch-deploy build. See the plan's Phase 0 section.
- `CLAUDE.md`, `docs/architecture.md` and `docs/onboarding.md` are rewritten for Astro as part of
  the port.
